# Grill: cc-pomodoro — AI CLI 原生番茄钟
Date: 2026-05-15
Rounds: 13

## Intent
做一个**面向 AI CLI（Claude Code、Codex CLI）的原生番茄钟应用**。当用户向 AI 发送一条指令的瞬间，自动开启一个专注周期；周期内屏蔽 AI 的完工信号与中间授权/反问，让用户能在 AI 处理任务期间安心做另一件深度工作（如读论文），到时间才回来一次性处理 AI 的全部输出。

要解决的具体痛点是**反应式焦虑**——「AI 一回复就立刻刷过去看、给下一条指令、再切回原来的工作、原本读到一半的内容忘了」这个反复打断深度工作的反射弧。

## Constraints
- **以人为核心**：保护人类用户的专注是最高目标，AI 在周期内完全空转等待是可接受代价。
- **不锁用户输入**："人手是控制不住的"——工具不做硬性强制（不覆盖终端、不拦截键盘），只屏蔽 AI 这一侧的视觉/听觉触发器。剩下的自律靠用户。
- **不让 AI 自治续命**：AI 答完就停，工具单纯屏蔽完工，不引入"AI 在隐瞒期间继续打磨/拓展"的自治行为（控制性优先于完工度）。
- **双 CLI 双 P0**：Claude Code 和 Codex CLI 都是硬需求，从 day 1 同步支持。
- **开源产品定位**：不只为作者一人造，规划后续扩展到 Gemini CLI / Copilot CLI 等。
- **早结束必须存在**：用户可以随时手动结束周期（弹"还剩 X 分钟，确定结束？[y/N]"），但保留软摩擦防止冲动。

## Key decisions

- **决定：番茄钟由"用户向 AI 发送指令"触发，one-task-per-cycle，周期内 AI 的所有 blocking 请求（授权、反问）一律延迟到周期结束。**
  - 理由：最干净的心智模型，匹配用户描述的真实工作流（发完指令转头去做别的）。
  - 备选已否决：独立计时器（非 dispatch 触发，用户手动起停）；多任务并发模式。

- **决定：周期内 UI 只显示倒计时，AI 的工作中/卡住/完工状态统统屏蔽。**
  - 理由：反应式焦虑由"看见 AI 状态"触发；显示"AI 在等你"等于把触发器再接回来。
  - 备选已否决（Q7 矛盾检验后）：显示 runtime 中间状态（"在干活/已停下"），因为只要暴露任意 AI 状态就会重新触发焦虑。

- **决定：AI 完工/卡死期间不显示任何提示，包括没有 spinner、没有进度条、没有"AI 已完成"。即使 AI 第 2 分钟就卡住等授权、剩 23 分钟纯空转，用户也只看到倒计时。**
  - 理由：保留任何"AI 需要你"的信号都会破功。
  - 备选已否决：终端图标变色 / 菜单栏小红点等"轻量提示"——会变成新触发器。

- **决定：早结束使用软确认（Y/N 弹窗），不引入 Forest 式连胜惩罚。**
  - 理由：用户的设计哲学是"尊重用户的当下判断"。
  - 备选已否决：长按 5 秒、敲完原始时长数字、shame counter 等重摩擦方案。

- **决定：实现方式 = 双平台各写一份原生 hook 集成（Claude Code Hooks + Codex CLI hooks），上层统一 stats schema。**
  - 理由：每个 CLI 的 hook 系统最贴近"屏蔽完工 + 阻塞授权"语义，避免 wrapper/终端插件那种侵入式工程。
  - 备选已否决：CLI wrapper（TTY 处理太重）、终端层插件（要适配 N 个终端）、仅 Claude Code MVP（用户拒绝单平台）。

- **决定：产品核心价值 = "CLI 原生的 Pomodoro 交互机制"——dispatch 触发、屏蔽完工、阻塞授权、CLI 内倒计时、早结束摩擦。这一整套 Forest + 关终端通知**做不到**，是这工具的存在合理性。**
  - 理由（Q11/Q13 矛盾消解）：用户承认自律 + 现有 Pomodoro 能解决 70% 的痛点；剩下 30% 不是 stats（stats 是次要附带），而是"CLI 原生集成的整套交互机制"本身。
  - 备选已否决：把 stats 提到 P0 同等位置；把工具退化为"普通 Pomodoro + 关通知"。

- **决定：周期结束后的衔接行为（AI 卡住、续接、跳过）做成用户可配置。**
  - 理由：单一默认无法覆盖所有场景。
  - 注：默认值未定，留给 PRD。

## Surfaced assumptions
- 反应式焦虑的触发是**视觉信号**（输出涌出、tab 过去看到状态、菜单栏图标变化），不只是听觉 bell——所以单纯关终端通知不够。
- 用户**没有**"AI 闲下来 = 我亏了"的生产力愧疚（Q3 明确否认）；要解决的是"立刻处理 AI 回复"的反应式焦虑，**不是**"AI 利用率焦虑"。
- 工具不试图保护用户免于一切分心——只切断"AI 完工 → 视觉触发 → 上前响应 → 上下文丢失"这一条特定反射弧。其他分心（手贱开手机、自己 cmd+tab 主动找事）不在解决范围。
- 这个工具的差异化壁垒**不是计时器**也**不是 stats**，而是**CLI 原生的交互整合**。如果未来发现 CLI 集成不重要，整个项目立项就崩了。
- 阿龙作为第二个真实用户的画像：研究生，高频用 AI CLI 做文献调研，希望腾出时间读更多论文——验证"反应式焦虑"不只是作者一个人的问题。

## Open questions（留给后续 brainstorm/PRD）
- **stats 数据模型**：每个 session 记录什么字段（duration / app / command 类型 / 完成状态 / 排队的授权数 / 早结束次数等）？粒度多细？
- **跨设备同步**：stats 是否需要后端同步？Q11.1 用户提到"跨设备体验不统一"暗示需要，但未正式确认。
- **后续衔接行为的默认值**：AI 周期内卡住、到点后是 (a) 自动续杯番茄钟 / (b) 给授权后切非番茄模式继续 / (c) 自动续一段——具体默认值未定。
- **Codex CLI 的 hook 能力调研**：是否真有跟 Claude Code Stop hook / PreToolUse hook 对等的钩子？这个不通整个 D 方案需要重选。
- **周期长度默认与可配置范围**：25/5/15 经典值还是别的？是否允许用户自定义？
- **多发指令的处理**：用户在一个周期内连续发多条指令应该被允许、排队、还是拒绝？
- **配置 UI 形态**：CLI flag？配置文件？slash command？
- **stats 可视化形态**：CLI 输出表格 / 本地 web dashboard / 导出 JSON？

## Out of scope
- 解决"AI 闲下来 = 我亏了"的生产力愧疚（用户明确否认存在这个心结）。
- 让 AI 在隐瞒期间自治续命（Q3 已否决：不好控制）。
- 锁用户输入 / 全屏遮罩 / 强制终端隐藏（Q4 已否决：人手控制不住、过度入侵）。
- 显示 AI runtime 状态来"诚实告知用户"（Q7 矛盾检验已证明会破功）。
- 重摩擦早结束（长按 ESC、敲数字、连胜惩罚）。
- CLI wrapper 实现路径（Q9 B）。
- 终端层插件实现路径（Q9 C）。
- MVP 阶段不包含 Gemini CLI、Copilot CLI（P2+，等 MVP 验证完）。
- Stats 不进入 P0（虽然必须有最小可用版本，但不是核心卖点）。

## Pre-mortem 风险（写入 PRD 风险表）
- **(a) 自己用两周觉得没那么有用**：用户承认 70% 痛点能被自律 + 现有工具解决；剩 30% 必须由"CLI 原生交互整合"撑住，**必须在 MVP 上线后 2 周内自我验证**——若发现自己其实不常打开，整个产品的存在合理性都要重审。
- **(c) 唯 1 真实用户**：除作者外仅识别出阿龙一个具体画像；在投入工程化抽象前，**建议作者先和阿龙做 15 分钟需求验证访谈**，确认 TA 真的会装一个 hook 工具到 TA 的 CLI 配置里。
- **(b) 双平台同步开发的卡点风险**：Codex CLI 的 hook 形态是开放疑问；写代码前**必须先做 Codex hook 能力调研**，确认它能否承载"屏蔽完工 + 阻塞授权"。否则 D 方案落空。
- **(d) 抽象层过早**：day 1 双平台 + 统一 stats 层，建议先写 Claude Code 原生实现走通，再用已固定的接口反推 Codex 层和 stats 抽象——避免空中楼阁。
